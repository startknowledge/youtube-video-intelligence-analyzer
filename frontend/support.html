Support

This page provides practical troubleshooting guidance for YouTube Video Intelligence Analyzer. Before reporting an issue, try the steps below and note the exact error message.

1. Check the YouTube URL

Use a normal public YouTube video URL such as a watch URL. Supported formats can include standard videos, Shorts, embedded URLs, or live URLs when the application's URL parser supports them. Remove accidental spaces or unrelated text from the URL.

2. Check whether the video is accessible

Open the video directly in your browser. If the video is private, removed, age-restricted, region-limited, or otherwise inaccessible to the application's data source, analysis may fail or return incomplete information.

3. Try again later

Temporary provider errors, rate limits, network failures, or maintenance can cause an analysis to fail. Wait a short time and try again. Repeated failures may indicate a configuration or API issue.

4. Transcript problems

A transcript may not be available for every video. Captions can be disabled, incomplete, unavailable in the requested language, or inaccessible through the current retrieval method. If transcript analysis is optional, the remaining metadata analysis may still be useful.

5. AI provider fallback

The application may use more than one AI provider. If a primary provider fails, the system can attempt a configured fallback provider. If all providers fail, a local heuristic fallback may produce limited results without advanced AI interpretation.

6. Browser troubleshooting

Try a current version of Chrome, Edge, Firefox, or another modern browser. Clear cached data if the interface appears outdated. Disable an extension temporarily if it interferes with requests or scripts.

7. CORS and network errors

A message such as “Failed to fetch” can be caused by a network request being blocked, a worker endpoint being unavailable, a CORS configuration problem, or an upstream provider failure. Refreshing the page can help identify whether the problem is temporary.

8. Do not share secrets

Support staff should never need your API key, password, browser cookies, private token, or other authentication secret in a normal support request. Remove such information from screenshots and logs before sending them.

9. What makes a useful bug report?

  • Exact page or feature.
  • Steps to reproduce the issue.
  • Exact error message.
  • Public video URL, if relevant.
  • Browser and operating system.
  • Approximate time of failure.
  • Screenshot with private data removed.

10. Feature suggestions

Suggestions are welcome. Useful requests explain the creator problem being solved, the desired workflow, and why the feature would be valuable.

11. Contact support

If troubleshooting does not resolve the issue, use the Contact page. We appreciate concise, reproducible reports because they make technical investigation faster.
